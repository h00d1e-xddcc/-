# терминология

`Из коробки` - в изначальном состоянии, без установки дополнительных плагинов и пакетов  
`Runtime` - состояние запущенного приложения  
`ОЗУ`,`Ram` - оперативная память  
`GPU` - видеокарта  
`CPU`, `камень`, `кристалл` - процессор  
`Поле`, `переменная`, `var/iable` - кусочек ОЗУ, с выделенным типом данных  
`Constant`, `константа` - не меняемое поле  
`Prefab`,`префаб` - мини сцена, содержащая как один обьект, так и множество  
`Scene`, `сцена` - совокупность множества других сцен и обьектов  
`CLI` - Command Line Interface, способ взаимодействия через консоль  
`GUI` - Graphical User Interface, способ взаимодействия через интерфейс  
`Garbage collectr`, `сборщик мусора` - мини-программа, что удаляет не используемые поля ОЗУ  
`IDE` - Integrated Development Environment, среда разработки (текстовый редактор)  
`Some` - "какой-то", на данной странице используется как пример для 'существующей' ноды/переменной  
`Core loop` - основной цикл игрового опыта  
`MVP (Minimum Viable Product) - почти играбельная версия проекта`   
`Prototype`, `прототип` - первые наброски проекта, без особой детализации  
`Iteration`, `итерация` - повторный цикл чего либо, как физического действия, так и кода  
`Scope Creep` - Не плановое асширение объёма проекта, к примеру добавление платформеру RTS или кулинарию  
`Vertical Slice`, `вертикальный срез` - почти законченный по качеству фрагмент проекта  
`OOP`, `ООП` - Обьектно Ориентированное Программирование, организация на основе классов  
`SOLID` - пять принципов проектирования ООП кода  
`Class`,`класс` - шаблон, чертеж, по которому создаются конкретные объекты  
`Callback` - функция, используемая, если что-то пойдет не так  
`Coroutine` - сложная функция, с возможностью приостановки и продолжения   
`State Machine` - положение состояний, к примеру стоит на месте, идет, бежит  
`Multithreading` - исполнение функций в нескольких потоках  
`Draw Call` - команда от CPU к GPU для отрисовки чего либо  
`Bottle neck`, `горлышко бутылки` - узкое место, ограничивающее производительность системы  
`Profiler` - инструменты для поиска и анализа производительности  

# Ноды (узлы)

Все создаваемые на сцене обьекты в Godot это ноды.\
Каждая нода наследует какие-либо свойства от родителя,\
к примеру `Spite3D` наследует свойства `Node3D`,\
то есть, `position`, `rotation`, `visible` и так далее.

`Node3D`, `Node` `Node2D`, `Control` это базовые ноды, из которых наследуются остальные

> (!) `some_node.visible = false` скрыть ноду\
> Но не все ноды можно скрыть, к примеру `Node` и ее дочери не скрываемы.   
>(!) `queue_free()` поставить ноду в очередь на удаление   
>(!) `free()` удалить ноду насильно, не дожидаясь ничего    
  
Так же еще важно упомянуть, что `Node3D` в своих векторных значениях, аля `rotation`, `position`,\
имеет в себе вектор с тремя значениями, в то время как `Node2D`, имеет двух значный вектор, `Vector3` и `Vector2` соответсвенно.\
Для разворота ноды, лучше всего использовать `rotation_degrees`, чтобы использовать `Vector3` для поворота,\
Так же можно использовать `Euler` и `Quaternion`, но лучше по началу не замарачиватся, чтобы не запутатся.\
>(!) Поворот по умолчанию идет в мередианах, а не в обычным `Vector3`  
Еще можно использовать `some_node.look_at(Vector3(0,0,0))`, для того, чтобы повернуть обьект в точку

Так же следует добавить о том, что\
- `Node3D` нода используемая для трехмерного пространства\
- `Node2D` нода используемая для двухмерного пространства\
- `Node` нода, что используема примерно в никаких ситуациях\
- `Control` нода используемая для создания интерфейса

Интерфейс лучше делать из `Control`'ьных нод, аля `ColorRect` или `TextureRect`.\
Обычные `Node` желательно вообще не использовать, так как он не будет наследовать позицию от родителя.\
# дочерние ноды

`get_node("Childame")` достать ноду по имени, от текущей ноды\
`get_node("user/seleton/mesh")` если нода глубже\
`get_node("/root/main/world/user")` абсолютный путь от корня\
`get_child(some_int)` индексное обращение

> (!) При создании нового обьекта, нужно добавить его на сцену к любому обьекту, чтобы его можно было физический увидеть.\
> В противном случае, нода не будет работать, к примеру `AudioStreamerPlayer` не может проигрывать звук.  
  
>(!) Дочерние ноды используют систему координат относительно своей материнской ноды,  
> для использования глобального положения, то есть относительно мировых координат,   
> надо использовать global, в следствии должно получится `global_position` или `global_rotation_degrees`

# поля вектора

`Vector2`,`Vector3`,`Vector4` сгруппированный `Float`, пример `Vector3(9.8, 0.0, -1.1)`\
`Vector2i` и `Vector3i`,`Vector4i` сгруппированный `Int`, пример `Vector4(57, -106, 24, -5000)`\
вектора имеют словари с базовыми значениями,\
`ZERO, ONE, INF, LEFT, RIGHT, UP, DOWN, FORWARD, BACK`\
к примеру `Vector3.ZERO` == `Vector3(0, 0, 0)`\
еще можно поставить `-` перед вектором, чтобы получить его отрицательное значение\
к примеру `-Vector3.ONE` == `Vector3(-1, -1, -1)`\
Для того, чтобы обратится к конкретному значению вектора, нужно поставить точку и выбрать направление,  
Направления `X`,`Y`,`Z`,`W`, пример `some_vector.z = 3.15`  
  
>(!) `Vector3i(Vector3(1.3,0,.1)) преобразовать Vector в Vectori

# enum
`enum` набор констант  
  
Обьявление `enum`  
```
enum some_directions { UP, RIGHT, LEFT,
DOWN, FORWARD,
BACKWARD}
```  
  
`some_directions.UP` достать значение из словаря    
  
Так же можно задавать явный тип   
И не обязательно писать капсом, или писать 'some` тоже не надо.   
Но все же, для чистоты кода, значения в `enum` пишутся капсом.  
```
enum some_enum_values {
some_value = 1.1
some_another_value = 10.8
}
```
  
`@export var enum_value : some_enum_values` можно использовать в поле  
  
```
enum list_of_planets { SUN, PLUTONIUM, WXDS, SATURN, JUPITER, DIRT}

var planets : list_of_planets

func some_match_test() :
  match planets :
    list_of_planets.SUN : print("sun is not a planet")
    list_of_planets.PLUTONIUM, list_of_planets.DIRT, list_of_planets.JUPITER : queue_free()
    _: OS.crash("")
    
```
  
>(!) для использования `match` указывать в сравнениях нужно именно сам `enum`
> для использования `в остальных случаях` надо использовать `_`

# массив dictionary

`var dict : Dictionary[]` обьявление словаря, значение словаря, как и ключ может быть чем угодно\
`var dict : Dictionary[id : String, name : String]` обьявление словаря с явным типом `String` на `String`\

`for dict.keys() in dict` перебор ключей, циклом\

# логические операторы

Пример использования `if` и `else`

    if 57 != 42 :
        print("Дуже потужно") # если пятьдесят семь не равно сорока двум, вывести дуже потужно
    else : 
        print(257)  # иначе вывести двести пятьдесят семь
    if true == true : print(true) # можно писать в одну строчку, если нужно выполнить, к примеру одну функцию

`for`,`while` это основные циклы,\
>(!) цикл это повторяющийся кусочек кода\
`while` будет исполнятся до тех пор, пока значение == `true`\
`while true :` будет повторятся вечно\
`while some_float < 2.4 :` пример с `float`

`for` будет исполнятся указанное количество раз\
`for i in range(57)` выполнить цикл 57 раз\
`for a in Array.size()` выполнить цикл столько раз, сколько в массиве значений

Так же еще стоит упомянуть о `pass`, `return`, `continue` и `break`,\
- `pass` просто пропускает часть кода\
- `return` прерывает функцию, и отдает значение по умолчанию `void`, но может быть и другое значение\
- `continue` пропускает действие цикла, и начинает его еще раз\
- `break` просто прерывает цикл, и продолжает исполнение функции

# загрузка файлов из проекта\
Для загрузки можно использовать `load()` или `preload()`, оба они делают примерно одно и тоже, только с своим подходом

    func load_some() :
        var some_prefab = load("res://resource/prefab.tscn").instantiate()`
        get_node("/root").add_child(some_prefab)

пример загрузки префаба из директории проекта,\
>(!) `get_node()` здесь используется для добавления ноды на сцену, то есть для того, чтобы его можно было увидеть физический

`load()` загружает на лету\
`preload()` загружает заранее и требует `const`\
>(!) для того, чтобы не танцевать в слепую, лучше перетащить префаб из директории проекта в скобочки функции

> (!) для того, чтобы понять какой из них нужен, стоит взглянуть на ситуацию,\
> то есть если надо просто загрузить префаб, то `preload()`\
> ну а если нужно подгрузить не явный префаб, к примеру с `randi_range()`, то `load()`\

# сохранение/загрузка ресурсов
> Обычно производится через `ResourceSaver`/`ResourceLoader` соответственно\
> (!) Путь надо указывать абсолютный.

Каталог проектов в системах,\
`"user://" == "%APPDATA%\Godot\user\some_project"` для систем с Окна 7+\
`"user://" == "~/.local/share/godot/app_userdata/some_project"` для систем Linux

`ResourceSaver(some_resource, "user://fnat.tres")` сохранить `.tres` в каталоге пользователя, см. строчку выше\
`ResourceLoader("user://fnat.tres")` загрузка ресурса, из каталога пользователя,\
>(!) желательно в конце добавлять класс ресурса, чтобы Godot явно понимал с чем работает\
`var some_loaded_resource = ResourceLoader("user://fnat.tres") as fnat_save` пример загрузки ресурса в качестве класса ресурса  
  
`FileAccess.file_exists("user://fnat.tres")` используется для проверки существования ресурса  
  
> (!) `"fnat"`здесь используется в качестве примера, это может быть любой другой `String`.\
> (!) так же можно сохранять и выгружать не только `.tres`, а еще и `.res` картинки, меши и так далее.\
> (!) при загрузки сцены, надо добавить `preload().instantiate()`
> (!) при загрузки ресурса, добавлять `instantiate()` не надо
# autoload\
> `Global Autoload`, или же `Singletone`, это нода, что указана в наследовании скрипта.\
> При запуске создается экземпляр этой ноды, под нодой `"root"`,\
> То есть можно получить к нему доступ через `get_node("/root/some_autoload")`\
> (!)В инспекторе до runtime нельзя предпоставить значения у `Autoload`.\
> В таких случаях использовать `_ready() :` и ниже писать `get_node()`\

## Шейдеры

Это мини программы, которые работают именно с видеокартой, указывая ей, как надо рисовать графику.\
Но шейдеры не обязательно должны работать с видеокартой, так же можно и с процессором, но будет не так эффективно.

`some_mesh.set_instance_shader_parameter("albedo", color)` изменить параметр у меша\
`some_mesh.get_instance_shader_parameter("albedo")` получить параметр у меша\
для окрашивания модели, нужно зайти в `GeometryInstance3D` > `Instance Shader Parametrs` и изменить `Coloring` на нужный цвет.\
>(!) эти методы актуальны, если у параметра в начале стоит `instance`

Надо будет написать потом про работу с шейдерами, займусь как нибудь на досуге.

примитивное окрашивание

    shader_type spatial;
    render_mode blend_mix, depth_draw_opaque, cull_disabled, diffuse_burley, specular_schlick_ggx;

    uniform vec4 albedo : source_color; // основной цвет (оставить белым)
    instance uniform vec4 coloring : source_color = vec4(1.0, 1.0, 1.0, 1.0); // окрашиваемый цвет
    instance uniform float tint : hint_range(0.0, 1.0) = 1; // зона окрашивания, 0 красить всю модель, 1 красить только ffffff

    fragment{
        vec4 albedo_tex = texture(texture_albedo, base_uv); // основная текстура, к примеру палитра
        ALBEDO = albedo.rgb * albedo_tex.rgb; // основное окрашивание модели
        float mask = step(tint, ALBEDO.r); // определение цветов закраски
        ALBEDO *= mix(albedo.rgb, coloring.rgb, mask); // окончательное окрашивание
    }

> (!) данный шейдер не универсален, лучше всего он подходит, если у текстуры нужный для покраски цвет явно `#FFFFFFF`,\
> В остальных случаях, он может как красить всю меш, так и ничего не делать.\

# Аудио
По большей части не имеет значение какого формата звуки, `ogg`, `vaw`, `mp3`, `flac`, `aac` итд.\
В разработке основными форматами являются `ogg`, `vaw` и реже `mp3`,\
- `ogg` это хорошо сжимаемый формат с потерями, но на разжатие уходит больше времени, чем у других форматов\
- `vaw`это буквально сырой файл, он не сжимается, и воспроизводится почти мнгновенно\
- `mp3` это что-то среднее между первыми двумя\
>(!) По большей части, разница между ними только в сжатии и разжатии.

| формат | расжатие | пример использования | длительность | тип сжатия | сердний вес |
|:--:|:--:|:--:|:--:|:--:|:--:|
| MS vaw | \~0 мс | короткие звуки, удар, нажатие, шаг | \<1 секунд | без потерь | очень большой |
| mp3 | до \~100 мс | то же что и с `vaw`, только немного длинее | 2-10 секунд | с минимальными потерями | зависит от сжатия |
| ogg | до \~350 мс | музыка, эмбиент, голосовые реплики | >10 секунд | с большими потерями | маленький |

> (!) Эту таблицу не стоит воспринимать как конатастанцию последнего слова,\
> Некоторые форматы позволяют выбрать степень сжатия аудио, что тоже влияет на задержку и вес.\
> (!) И не обязательно стараться переконвертировать постоянно файлы, можно обойтись и одним `ogg`,\
> только стоит в таком случае учитывать задержку при воспроизведении.\
> (!) `ogg` сжимает с большими потерями, но человек особой разницы не услишыт.

По мимо основных трех, еще иногда используется `flac`, это сжимаемый формат без потерь.\
Он отлично подходит для новел, записанных в живую инструментов, мелодий, вокалов и так далее.\
>(!)Но как по мне, можно просто в тупую в `ogg` все форматнуть, раз человек все равно не услышит разницы.

# лицензии
Обычно при использовании чужих нароботок, нужно указывать автора

|:--:|:--:|:--:|:--:|:--:|
| MIT | да | да, использовать отметку,<br>`Copyright (c) [Год] [Имя автора]` | да | сохранить лицензию и<br>плашку об использовании |
| CC0 | да | нет |  | нет |
| CC BY 4.0 | да | да | да | указать автора, лицензию,<br>ссылку и отметку использования |

Подробнее о CC подобных
- CC0 (Public Domain) Самый свободный вариант. Автор отказывается от прав в максимально возможной степени, разрешая использовать, изменять и распространять материал без обязательной атрибуции. Удобно для текстур, спрайтов, звуков и моделей.
- BY (Attribution) Требует указания автора. Например, можно взять текстуру, перекрасить её, использовать в коммерчестве и продавать проект, если соблюдены требования к атрибуции.
- SA (ShareAlike) Если создается и распространяется адаптированная версия ассета, то надо требования о той же или совместимой лицензии. Это не означает, что вся весь проект автоматически должен быть открытым.
- NC (NonCommercial) Запрещает коммерческое использование без отдельного разрешения автора. Проблема в том, что коммерческое использование не ограничивается только прямой продажей ассета. Например, монетизируемый проект тоже может подпадать под это ограничение  
- ND (NoDerivatives) Нельзя распространять адаптированные версии материала. Для ассетов это неудобно: изменение изображения, переработка модели или редактирование музыки могут создать проблемы. При этом использование неизменённого материала в составе не обязательно запрещено.  

Ограничения DRM у CC-BY и CC-BY-SA могут стать проблемой при публикации на некоторых платформах. OGA-BY специально создана для использования без этого ограничения.  
Если ассет/проект предлагается под несколькими лицензиями, можно выбрать наиболее подходящую. Например, если есть CC-BY и GPL, для закрытого коммерчества, обычно проще использовать CC-BY, соблюдая её условия.  
Экспорт проекта != публикации исходников. Встраивание ресурса и распространение самого исходного файла могут иметь разные последствия с точки зрения лицензии.  

> (!) данный перечень не заменяет полные текст лицензий.  
> Особенно осторожно нужно обращаться с GPL и LGPL.

Скорее всего, получить полностью весь рабочий проект не получится, но чем меньше проект, тем выше шанс на это.   
Вообще, при использовании чужих картинок/звуков, особенно из популярных произведений, не приветствуется,формат для 3D печати   
Как в Steam,EGS,GOG так и издательствами и с большой вероятностью itch.   
Автора могут подать DMCA или что-то похожее, в следствии чего проект прикроют, а разработчика накажут.   
Но, если проект не коммерческий, это может немножко снизить уровень наказания. 
Рекомендуется использовать ~~спизженные~~ декомпилированные ресурсы только в локальных проектах.
